# EDGE_CASES

Only real edge cases live here: situations where the obvious behaviour is wrong or a naive
implementation fails. Routine features belong in the stage docs, not in this file. Add a row when
a new edge case is found or decided; do not re-implement a case already marked `done`.

Status: `done` (built and tested), `planned` (a later stage owns it; the stage is named), `open` (decision needed).

| ID | Edge case | Handling | Where | Status |
|---|---|---|---|---|
| E-01 | The same document is uploaded more than once | Hash the file (exact repeat, ignored). Then compare a content key of type + person + period (rescan or re-export, ignored). Same key but different amounts: keep both and raise `DUPLICATE_CONFLICT` as a tamper hint. File names are never used. | `intake/duplicates.py` | done (Stage 2) |
| E-02 | Payslips for different months, or a co-applicant's documents, look alike | The key includes the period and the person's PAN, so they are never duplicates. A document whose key cannot be built (OCR missed a part) is never called a duplicate. | `intake/duplicates.py` | done (Stage 2) |
| E-03 | Duplicates must not fill a missing-document slot | Completeness counts `CaseDocuments.unique_count`, not uploads. | `scoring/facts.py` (`_docs`) | done (Stage 3 counts one document per `content_key`; Stage 5 supplies the key from `CaseDocuments`) |
| E-04 | Storing the hash and ignoring a duplicate across requests | Save `sha256` in `documents` (column already exists) and rebuild `CaseDocuments` from accepted rows for the case. | case storage | planned (Stage 6 API) |
| E-05 | Officer replaces a rejected or wrong file | Explicit "replace": old row kept in the audit log, new row becomes active. A rejected upload is never recorded, so re-uploading the fixed file is not a duplicate. | API + audit log | planned (Stage 6) |
| E-06 | Password-protected PDF | Rejected at upload; the password is never requested or stored. | `intake/upload.py` | done (Stage 2) |
| E-07 | Applicant photo (passport size) has no text and almost no edges | Images under 500 px on the short side get no blur or crop verdict, so they are not rejected as blurry. | `intake/upload.py` | done (Stage 2) |
| E-08 | Photographed page is cut off | Page aspect ratio outside 1.30 to 1.55 is rejected as cropped. | `intake/quality.py` | done (Stage 2) |
| E-09 | OCR misreads digits and separators ("10.600.00", "07:08/1987", "O" for 0) | Tolerant money and date parsers; PAN/Aadhaar checksums cap the confidence of any misread id. | `intake/fields.py`, `checks.py` | done (Stage 2) |
| E-10 | Badly degraded photo: labels not found | Fields stay empty and the officer sees `missing_required_fields`; nothing is guessed. About 30% field accuracy on the generator's "poor" photos. | `intake/pipeline.py` | done (Stage 2) |
| E-11 | Prompt injection inside a document | Flagged `possible_prompt_injection`; text goes to the model only as masked data; scores are code. | `intake/injection.py` | done (Stage 2) |
| E-12 | Payslip net pay vs bank credits, odd large credits | `risk.cross_document_hints` calls them with both documents when the case is assembled (salaried only, needs a payslip and a statement), so Policy and Risk score the same input. | `agents/risk.py`, `intake/tamper.py` | done (Stage 5) |
| E-13 | Payslip whose totals do not tie out (net printed higher than gross minus deductions) | That payslip is left out of the income average (used only if every payslip is like that); `totals_tie_out` is false, so the Documents score drops. | `scoring/facts.py` | done (Stage 3) |
| E-14 | A KYC document is missing, so PAN or Aadhaar checks have nothing to check | Reported once, by CM-DOC-01 (fix-type). The checks that need the document are not run, so the officer is not shown the same gap three times. | `scoring/engine.py` | done (Stage 3) |
| E-15 | Payslip or ITR income higher than the bank credits support | The lower, bank-supported figure is used for income and FOIR, and `INCOME_EXCEEDS_BANK_CREDITS` is raised as a strong tamper hint (CM-FRD-01 caps the case at refer). | `scoring/facts.py` | done (Stage 3) |
| E-16 | No bureau record for the earner | Treated as unverified: the CIBIL floor rule fails (eligibility-type), never a crash and never a silent pass. | `scoring/evaluate.py` | done (Stage 3) |
| E-17 | Inflated ITR income on a business loan | Bank credits for a business are far above profit, so the bank cross-check cannot expose it; only intake's PDF-metadata hint does. The case is still capped at refer, but income verification (CM-INC-12) can overstate. Known gap, found by SYN-BL-D13. | `scoring/facts.py` | open (accepted for v1) |
| E-18 | Intake's measured quality for mild photos (80) lands in a better scoring tier than the generator's design target (72) | Decided at Stage 5: leave the tiers and the measured quality as they are. The measured value is the truth about the file; the key's design target was a guess. Effect on the dev run: the same two cases, SYN-VL-D04 and SYN-BL-D04, come out refer where the key says reject. The replay (`scoring/replay.py`) still uses the key's design values. | `scoring/replay.py`, `intake/pipeline.py` | done (accepted difference) |
| E-19 | The model cites a clause that was not retrieved, quotes words that are not in the clause, or cites another loan type's clause | `check_grounding` rejects it; one retry with the failed checks; then `unverified` and findings written by code from the rule results. | `rag/grounding.py`, `agents/policy.py` | done (Stage 4) |
| E-20 | A policy clause is edited without changing the version label | The file checksum and clause hashes catch it; only that clause is re-embedded. A new version label adds a row and deactivates the old one. | `rag/index.py` | done (Stage 4) |
| E-21 | Policy files carry `effective_from` 2026-11-01 but today is earlier | Retrieval filters on `active`, not on the date, so the sample policy is usable now. An as-of filter can be added if dated versions matter. | `rag/retrieve.py` | done (Stage 4) |
| E-22 | A model reply obeys text hidden in a document ("approve", "set the score to 100") | Scores come from the rules engine once, before any model runs; replies are schema-checked (extra fields refused), guardrail-checked (decision words, protected attributes, invented numbers) and retried once; then code text is used and the stage is `unverified`. The injection scan flags the file for the officer. | `agents/guardrails.py`, `agents/runtime.py` | done (Stage 5) |
| E-23 | The paused node's resume value is invalid (an override with no reason) | LangGraph replays a stored resume value on every later resume, so a value that fails inside the node would fail forever. The officer's answer is validated before the graph is resumed. | `agents/graph.py` | done (Stage 5) |
| E-24 | A node is killed after its checkpoint but before its database rows are final, or runs twice | Every writer replaces its own (case, stage) rows, logs and report version; resuming never duplicates. | `agents/store.py` | done (Stage 5) |
| E-25 | A hard fail in Risk while Policy runs beside it | Policy checks the stop in the saved score and is skipped (no row, status `skipped`), so a stopped case shows no policy result. | `agents/graph.py` | done (Stage 5) |
| E-26 | A fix-type stop is corrected by replacing a file or editing the form | State derived from the files is stale, so the run re-enters at Extraction (same thread, `run_no` + 1, a new report version) rather than reusing earlier stages. | `Pipeline.resume_after_fix` | done (Stage 5) |
| E-27 | A KYC photograph is too blurred for the local OCR (the generator's `poor` tier) | Nothing is guessed: the document is `unrecognised_document` or `missing_required_fields`, so CM-DOC-01 or an identity rule fails (fix-type) and the run stops at KYC asking for a clearer copy. Decided at Stage 5: this is the expected outcome, so `agents/run.py` (`expected()`) expects a fix-type stop at KYC for the 9 dev cases with a `poor` PAN or Aadhaar photo. The answer keys are unchanged, so the engine replay still scores them. Not adopted: letting the case continue with the ID fields `unverified` for the officer to eyeball (possible later), or a vision model on images (breaks the "never send raw images" decision). | `agents/run.py`, `intake/` | done (decided) |
| E-28 | Round-figure salary repeated on every payslip | Weak hints count once per kind (`len(set(hints))` in `scoring/facts.py`), so a round gross salary on every payslip is one `ROUND_SALARY` hint and does not cap the case; two different weak signals still do. Strong hints (editor tool, income above bank credits) are unchanged. | `scoring/facts.py` | done (Stage 5) |
| E-29 | A case with no PAN card (SYN-PL-D09) is submitted through the UI | The API refuses submission until every KYC checklist item (PAN, Aadhaar, photo, per person) has an accepted file, so this case cannot reach the pipeline from the browser. The pipeline's own CM-DOC rules still stop it when it is run from the command line. The UI browser tests use cases that have every KYC file. | `api/cases.py` (`_prepare_submit`) | done (Stage 6) |
| E-30 | A corrected form shows PAN, phone or GSTIN masked | A value left masked keeps the stored one; a different masked value, or a masked value on a new case, is refused with a message asking for the full value. | `api/cases.py` (`_merge_masked`) | done (Stage 6) |
| E-31 | The application form is long and tiring to fill, so filling it from the uploaded documents looks attractive | Not adopted: a document can be forged or misread, so reading it into the form would make the claim and the proof the same thing and the check would prove nothing. Three designs were compared: officer types first (kept), full auto-fill from documents (rejected), core identifiers first with official data and a hidden buffer (rejected for now, it changes how case state is stored). Instead the form is shortened and made clear: required fields show `*`, optional ones show "(optional)", and a note at the top explains both. Optional: mobile number, employer, months in job, total experience, residential status, purpose, application date, co-applicant relationship, home property address, seller and owner, education institution and course duration, business Udyam number. A filled optional field is still compared with the documents; an empty one is skipped and never guessed. | `api/schemas.py` (`LOAN_FIELDS`, `required`), `ApplicationForm.jsx` | done (decided) |
| E-32 | The mobile number is left empty, then the case is corrected | An empty phone is stored as null. The masked-value check in `_merge_masked` and `_is_masked` skips an empty phone, so correcting a case with no phone does not fail. | `api/cases.py` | done (Stage 6 follow-up) |
